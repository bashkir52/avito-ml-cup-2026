## Следующий эксперимент

**Проверь, добавляет ли предобучение на последовательностях действий полезный сигнал для ранжирования лент.** В исходном train 512 Parquet-файлов, 3 151 208 лент и 246 745 836 показов. Потоково читай истории из `competition/train/impressions` и используй 128-мерные эмбеддинги объявлений из `competition/train/item_embeddings/data.memmap`. Предобучение переносит закономерности из самих последовательностей действий в модели ранжирования.

1. **Построй задачу предсказания следующего товара.** В исходных `history__*` события упорядочены от новых к старым. Для каждого обучающего примера подавай более ранние события и предсказывай следующее по времени. Выдерживай соответствие между ID товара, индексом эмбеддинга и типом события. Индекс `-1` означает пропуск. Используй существующие векторы товаров как входы кодировщика и для оценки кандидатов, в том числе товаров без обученного представления по ID. Если берёшь отрицательные из батча, исключай совпадающие с целевым товаром ID.
2. **Проверь обучение на небольшой выборке, затем масштабируй потоковый проход по train.** Проверь хронологию примеров, маски и пропускную способность. Начни с компактного энкодера, например GRU или одного блока каузального внимания, чтобы оценить саму идею предобучения. Выбирай длину истории, батч и размер модели по измерениям и качеству. Полный набор историй загружать в память не требуется.
3. **Дообучи на опубликованных откликах в лентах.** Сравни модель с предобучением и ту же архитектуру со случайной инициализацией при одинаковом дообучении. Кэш на 48 файлах даёт готовую основу с 23 111 632 кандидатами в целых лентах. Для дальнейшего масштабирования используй исходные train-файлы. Позиция прежнего показа отсутствует в val/test. Читай истории и эмбеддинги из соответствующих частей. Для обучения используй метки train, для выбора и оценки — метки val.
4. **Сохрани прогнозы и проверь комплементарность.** Сравни обе модели самостоятельно и в смеси с точными прогнозами отправленного ансамбля. NDCG на полных лентах — основной критерий. Проверь также топ-10 длинных лент с 101–300 кандидатами, где у ансамбля заметен запас для улучшения.

Для справки архитектура [SASRec](https://arxiv.org/abs/1808.09781) использует порядок действий для предсказания следующего товара, а [UniSRec](https://arxiv.org/abs/2206.05941) строит последовательную модель на признаках товаров. Для этого проекта достаточно сначала проверить компактную модель на имеющихся векторах.

## Оценка и решение о сабмите

- Основная метрика — полная NDCG с одинаковым весом каждой ленты. Дополнительно посчитай NDCG@10, NDCG@30 и число положительных в топ-10. Перед оценкой проверь соответствие ключей `feed_id` и `item_id` полным кэшам val/test.
- Ранний val содержит 5 766 лент. Вес смеси подбирай по двум последовательным частям на 3 749 и 2 017 лент. Поздний val содержит 8 657 лент, с половинами на 4 317 и 4 340. Зафиксируй модель, нормализацию и вес до открытия её поздних результатов. Разбиение воспроизводит `temporal_boundary` из `experiments/ranking.py`.
- Ориентир для Public — около `+0.003` к текущему ансамблю на позднем val с выигрышем в обеих половинах. Меньший прирост оцени по парному интервалу, устойчивости по времени и верхним позициям. Для сильного варианта собери Parquet и запусти `experiments/ranking.py audit`. Должны быть ровно 2 904 806 пар официального шаблона, конечные scores и отсутствие ничьих внутри лент.
- Запиши в `materials/EXPERIMENTS.md` архитектуру, фактический объём данных, способ построения примеров, seed, контроль, результаты по блокам и команды воспроизведения. Модели и прогнозы сохраняй в отдельных каталогах `experiments`.

Среда проекта — Windows, PowerShell, `uv`, Python 3.11. Версии библиотек и `$rankingPackages` указаны в начале `materials/EXPERIMENTS.md`, для прежних нейросетевых запусков использовался PyTorch `2.10.0`. Локальный набор `python -m unittest discover -s experiments` содержит 49 тестов.
